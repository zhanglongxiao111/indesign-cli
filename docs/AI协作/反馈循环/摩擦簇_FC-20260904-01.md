## 簇 ID

FC-20260904-01　表格保真门禁在 html-indesign 0.2.10 必失败，同事用"删表格"绕过

## 证据

- 指标：`FIDELITY_GATE_FAILED` × `html.build_indesign`，字段 `table.rows`，代码 `FORWARD_TABLE_CHANGED`。08-19 起 2 个 session、2 台工位、2 个项目，作者包里**每一张表**都报错（D0486 1/1 张，C20260806 8/8 张）。
- 脱敏轨迹（来自 outDir 归档的 `forward-fidelity-report.failed-*.json`，单元格文本全部一致，只差三处）：
  1. `header`：expected `true`（HTML `<th>`）→ actual `false`。构建脚本 `_indesign_scripts/lib/hi_tables.jsxinc` 从不设置 `table.headerRowCount`；反向读取 `hi_reverse_tables.jsxinc:60` 只认 `headerRowCount` 或段落样式名含 header/heading/表头。
  2. `paragraphStyle`：expected 缺省（单元格没写 `data-id-paragraph-style`）→ actual `[基本段落]`。`forward-fidelity.js` `tableFacts()`（约 884-901 行）对 `cellStyle` 用 `isBuiltinNoneStyle` 过滤 `[无]/[none]`，对 `paragraphStyle` 没有任何内建样式过滤。
  3. 空白：`<td>` 内容以换行开头时 expected 首字符是 `\n`，actual 是空格。`normalizeLineEndings` 只统一 CRLF，不折叠空白（D0486 4 个单元格）。
- 后果：两个作者包的最终版都没有 `<table>` 了。D0486 的表格页现在是 `grid-item` 拼的文本框（保真报告 items 157 → 184）；C20260806 50 页包从 ≥8 张表变成 0 张。成品 INDD 因此没有真正的表格对象，后续人工编辑体验变差。
- 影响版本：indesign-cli 0.5.11 / html-indesign 0.2.10；从代码看 0.2.9 及更早同样存在。

## 建议通道

- 正常修复（html-indesign 仓库），三处都小：
  1. `hi_tables.jsxinc`：按 `row.header`（或首行全 `th`）设置 `table.headerRowCount`。
  2. `tableFacts()`：expected 未声明 `paragraphStyle` 时，actual 为 InDesign 内建默认（`[基本段落]` / `[Basic Paragraph]` / `[无段落样式]` / `[No Paragraph Style]`）视为一致；把 `isBuiltinNoneStyle` 扩成"内建样式"判定并同时用于 `cellStyle`。
  3. `tableFacts()`：单元格文本比对前折叠空白（`\s+` → 单空格并 trim），与正文 `compareText` 的口径对齐后一并复核。
- 顺带（快通道）：`FIDELITY_GATE_FAILED` 的 message 对 `table.rows` 差异只说"differs at field table.rows"，建议列出差异维度（header / paragraphStyle / text），否则 Agent 面对两份 5 行 JSON 分不清是内容错还是样式差。

## 承接测试

- 工具缺口类：`test/html-to-indesign/` 增加带 `<thead><th>` 且单元格无样式声明的 fixture，`auditForwardFidelity` 期望 0 error；真机 E2E 场景加一张表格，首轮构建必须 `verified: true`。
- 错误信息类：单元测试断言 `table.rows` 失败 message 含差异维度名。
- 复核指标：下期 `FORWARD_TABLE_CHANGED` 归零；同事作者包 `<table>` 数量不再为 0。
